# プロンプト集

**このファイルは生成物。手で編集しない。**
出典は `src/data/assets.js`。変更したら `npm run gen:docs` で作り直す。

## 使い方

各アセットのコードブロックを**そのまま丸ごとコピーして貼る**。
組み立てや読み替えは要らない。判断が必要なら、それは仕様の不備なので直す。

## 絶対の禁止事項

### 1. 看板の文字を画像に含めない

AI画像生成は日本語の文字をまともに描けない（崩れた漢字、存在しない字形）。
しかも生成し直すたびに変わる。**看板は文字のない板だけを生成し、文字は Canvas 2D で描く。**

### 2. 影と遠近を焼き込まない

ライティング・影・遠近は Three.js が付ける。
絵に影が描かれていると影が二重になり、即座に破綻する。
例外は「一枚絵」（結末）だけ。3D空間に置かないため。

### 3. 原作に描写があるものは、原作の記述を優先する

見た目を思いつきで足すと、原作と食い違う。実際に食い違っていた例:

| 対象 | 誤り | 原作 |
|---|---|---|
| 厨房の扉 | 真鍮の鍵穴が1つ | **大きなかぎ穴が二つつき、銀いろのホークとナイフの形が切りだしてある** |
| 塩壺 | 素焼きの壺 | **立派な青い瀬戸の塩壺** |

迷ったら青空文庫の原文を読む。仕様書 §7.0 に該当箇所を引いてある。

### 4. 面にマゼンタ背景を指定しない

床・壁・背景は板いっぱいに貼るテクスチャなので、
背景を抜く必要がないどころか**抜けてはいけない**。
ローダーもこの3種類はクロマキーを通さない（`chromaKey.js` の `SURFACE`）。

## レシピ

レシピが画角と技術指定の両方を決める。だから
`STYLE_BASE ＋ 対象 ＋ レシピ` を連結すれば、判断の余地なく完成する。

| レシピ | 枚数 | マゼンタ背景 | 透過処理 | 保存形式 |
|---|---|---|---|---|
| `floor` 床（面） | 3 | 不要 | そのまま使う | JPEG |
| `wall` 壁（面） | 2 | 不要 | そのまま使う | JPEG |
| `backdrop` 背景（面） | 3 | 不要 | そのまま使う | JPEG |
| `sign` 看板の板（抜き・文字なし） | 2 | **必要** | 実行時に抜く | PNG |
| `prop` 立て板（抜き） | 36 | **必要** | 実行時に抜く | PNG |
| `actor` キャラ（抜き） | 8 | **必要** | 実行時に抜く | PNG |
| `face` 表情（抜き） | 6 | **必要** | 実行時に抜く | PNG |
| `animal` 犬（抜き） | 3 | **必要** | 実行時に抜く | PNG |
| `scene` 一枚絵 | 7 | 不要 | そのまま使う | JPEG |

## STYLE_BASE（全アセット共通・変更禁止）

```
storybook illustration in delicate watercolor wash over fine copperplate etching linework, muted desaturated palette of aged ivory, dusty ochre, faded moss green and oxidized silver, Taisho-era Japanese art nouveau ornament, thin confident ink outlines, subtle laid-paper grain, restrained detail
```

絵柄の一貫性はここだけで担保している。一字も変えない。

## 生成の運用ルール

1. 生成物は **必ず `assets/raw/` に元のまま保存する。** AI生成は同じ絵が二度と出ない
2. 抜き板は `raw/` に置けばローダーが実行時にマゼンタを抜く。手作業で綺麗に抜いた版は `assets/textures/` に置くと優先される
3. 面（床・壁・背景）はどちらに置いてもよい。クロマキーを通さない
4. **看板・札に文字が混入した画像は捨てて再生成する。** 文字は Canvas 2D で描く
5. 絵柄がズレた画像は捨てる前に、Three.js のライティングとカラーグレーディングで吸収を試す（設計書 §4.5）
6. **床は向きのある幾何模様を避ける。** ヘリンボーンやシェブロンは継ぎ目のずれが一目で分かり、
   鏡張りで逃げることもできない（反転すると V 字の折り返しが継ぎ目より目立つ）。
   幅の違う板を不規則に並べる、といった絵にすれば両方隠れる。
   `mountain/ground.png` のように**鏡張りで敷く床**は、継ぎ目を合わせる必要がまったくない。
7. **形式とピクセル数はツールが勝手に決めることがある。** 従わなくてよい。
   プロンプトの指定どおりに出なかったら、`npm run fit:assets` で下見して `-- --apply` で揃える
   （面は JPEG に変換して縮小、抜き板は PNG のまま縮小。元のファイルは `assets/_原本/` に退避される）。
   ★**「重い」の原因を取り違えないこと。** 面が 2MB を超えるのはピクセル数ではなく PNG で保存したせい。
   同じ 1024x1024 の絵が JPEG なら 1/4 になる（実測 2206KB → 515KB）。
8. **壁は床より明るく生成する。** キー光が上から来るので、同じ明度だと壁が半分の明るさになる（設計書 §4.4.1）
9. **「同じものの差分」は、必ず元の絵を参照して生成する。**
   別々に生成すると木目も位置も合わず、重ねたときに継ぎ目が見える。
   参照画像（img2img）や同一シードで、変える部分だけを変える。該当する組:

| 元 | 差分 | 変えるところ |
|---|---|---|
| `rooms/06_kitchendoor/kitchen_door.png` | `rooms/06_kitchendoor/kitchen_door_eyes.png` | 鍵穴から眼玉が覗いているだけの差分 |
| `rooms/01_entrance/chandelier.png` | `rooms/01_entrance/chandelier_dark.png` | 明かりが消えているだけの差分 |
| `rooms/04_wardrobe/coat_rack.png` | `rooms/04_wardrobe/rack_toppled.png` | 倒れているだけの差分 |
| `rooms/04_wardrobe/mirror_ornate.png` | `rooms/04_wardrobe/mirror_cracked.png` | 割れているだけの差分 |
| `rooms/05_oilroom/cream_jar.png` | `rooms/05_oilroom/cream_spilled.png` | こぼれているだけの差分 |
| `rooms/06_kitchendoor/serving_table.png` | `rooms/06_kitchendoor/butcher_cloth.png` | 染みがあるだけの差分 |
| `characters/dog/alive.png` | `characters/dog/fallen.png` | 同じ犬2匹。倒れているだけの差分 |
| `characters/player/stage0.png` | `characters/player/stage1.png` | 同じ人物。脱いだ段階だけの差分 |

   立ち絵は stage0 → stage1 → stage2 → stage3 と順に参照して繋ぐ。
   同じ人物に見えなければ、服を脱いでいく話が成立しない。
