# Demo_8 — 『注文の多い料理店』

宮沢賢治「注文の多い料理店」（1924年 / パブリックドメイン）を原作とした、探索＋脱出のブラウザゲームデモ。

**成果指標は「面白さ」一本。** 原作への興味は副産物として扱い、成果指標には含めない。

---

## 一行でいうと

**丁寧語で少しずつ武装解除されていく12分。何を差し出し、何を掌に握り込むかを選び続け、気づいた瞬間に来た道を逆走する。**

### アセットのドキュメントは生成物

`プロンプト集.md` と `アセット一覧.md` は **`src/data/assets.js` から生成する。手で編集しない。**

```
npm run gen:docs      # プロンプト集とアセット一覧を作り直す
npm run check:assets  # 投入した絵を検査する（寸法・マゼンタ・継ぎ目・容量）
```

### 絵の置き場所

| 種類 | 置き場所 | マゼンタ背景 |
|---|---|---|
| 抜き板（家具・小物・キャラ・看板・犬） | **`assets/raw/`** | **必要**（実行時に抜く） |
| 面（床・壁・背景・結末の一枚絵） | `assets/textures/` でも `raw/` でも可 | 不要 |

**`assets/textures/` は「すでに抜けている完成品」の階層。** ここに置いた絵はクロマキーを通らないので、
マゼンタ背景のまま置くと背景が残る。**透過処理はこちらでやる必要はない。`raw/` に置けばよい。**

散文のドキュメントとコードを二重管理すると必ずずれる（実際にコードが使う6枚が一覧から漏れていた）。
`test/assets.test.mjs` が、コードの参照と `assets.js` のずれを検出する。

## 技術構成

- Three.js（importmap ＋ unpkg CDN / `three@0.184.0`）による**板ポリ2.5D**
- 素の ES Modules。**ビルド工程なし**
- `node --test` で `test/*.test.mjs`
- 横向き固定 16:9。入力は `pointerdown` 統一
- **音声なし**（設計を音に依存させない）

```
npm test      # ロジックのテスト
npm run serve # ローカルサーバ
```

---

## 開発の要点

1. **絵がゼロの状態で通しプレイできるようにするのが先。** `src/systems/` は Three.js を import しないため、`node --test` で全ロジックを検証できる
2. **数値バランスは遊ばないと決まらない。** 仕様書 §6.4 の数値は初期値であり、調整前提
3. **看板の文字を AI 生成画像に含めてはならない。** 文字は Canvas 2D で描く
4. **影と遠近を絵に焼き込んではならない。** ライティングは Three.js が付ける

## 開発サーバについての注意

`python3 -m http.server` は `Cache-Control` を送らないため、**Chrome が ES モジュールを
古いまま使い続ける**。コードを直したのに画面が変わらない、という状態になる。
Phase 3 で実際にこれが起き、自動検証が古いコードを検証していた。

`npm run serve`（`scripts/serve.py`）は `no-store` を必ず付けて配信する。**必ずこちらを使う。**

一度キャッシュ済みのエントリが残っている場合は、ヘッダを直しても
ネットワークに出ないため効かない。**ポートを変えてオリジンを変える**のが最も確実。
